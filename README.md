# Geometric Manifold Computing

Curvature-governed resilience research prototype.  
Steven Leake / Monarch X / Sophia

Distributed state is treated as a graph whose local geometry stands in for operational health. Nodes carry load and capacity. Edges carry a utilization contrast. A graph-Laplacian curvature proxy, a density correction, and a fail-closed admission gate decide whether a proposed load transfer may run. Every attempt, admitted or rejected, is appended to a hash-chained JSON receipt log that can be replayed.

## Boundary

This repository is a **single-process simulation**.

- Curvature is a **graph-Laplacian proxy**, not intrinsic Ricci curvature, and not a proof that a smooth manifold exists.
- There is **no physical validation**, no actuation of real infrastructure, and **no universal anomaly-detection guarantee**.
- The Rust crate is a numerical kernel. It does not authenticate operators or authorize effects outside the simulation.
- Passing the research gates shows numerical consistency of this model. It does not show semantic truth about arbitrary networks.

Model id: `gmc.graph-resilience/1`  
Receipt schema: `monarch.gmc.receipt/2`

## Technical approach

Three mechanisms, scoped to this prototype:

1. **Curvature convergence.** Utilization on a ring is scored by a combinatorial Laplacian. A deviation from a baseline curvature above the policy threshold is reported as a detected shift. A scenario with no geometric change stays quiet. That is an observability boundary, not a claim that every real failure is visible.
2. **Density correction.** Proposed transfers move load from higher energy-gradient nodes toward lower ones, with a per-edge Newton step clipped by the transfer budget and by capacity. The step is admitted only when mass is conserved and Dirichlet energy does not increase.
3. **Admissibility gating.** Before a transfer commits, the gate checks edge membership, snapshot digest, epoch, operator capability (`simulate.transfer`), finite budget, capacity bounds, conservation, and energy descent. Anything else is rejected and the state is left unchanged.

Python (`gmc.py`) is the research harness: scenarios, gates, receipts, replay. Rust (`rust/`) is the performance-oriented kernel for curvature, energy, and a checked transfer, plus a C ABI for curvature. The two are parallel implementations of the same proxy, not a claim that one calls the other.

## What the simulation exercises

Seed `1599`, 12-node ring, 240 sweeps, budget `0.05` per transfer. Regenerated by `python3 gmc.py simulate`.

| Scenario | What is injected | Detector | Energy |
|---|---|---|---|
| overload | node 0 load 0.95, node 1 load 0.05 | score 1.35, detected | falls to ~0 |
| capacity_degradation | node 0 capacity 0.55 | score 0.82, detected | falls to ~0 |
| partition | edges `{0,11}` and `{5,6}` removed; random loads | detected | each side equalizes; the cut remains |
| adversarial | NaN amount, then a transfer signed by another operator | not a geometric event | both actions rejected |
| unobservable_failure | no perturbation | score 0, not detected | stays 0 |

Mass error on the overload run was about `1.8e-15`. Rejected adversarial actions do not move state. A byte-level change to a receipt fails replay.

Research gates on the intact ring:

1. manifold admissibility — graph validity only
2. density bias correction — no isolated nodes; weights sum to 1
3. contrast reconstruction — numerical identity, max error 0
4. curvature convergence — periodic finite-difference check of `sin` at 32 / 64 / 128, max errors about `3.2e-3`, `8.0e-4`, `2.0e-4`

Gate 4 is not an arbitrary-graph test and not a physical test. A nonpositive capacity fails closed at gate 1. An edgeless graph fails gate 2.

## Run

Python 3.10+, standard library only.

```bash
python3 gmc.py test
python3 gmc.py verify
python3 gmc.py simulate
python3 gmc.py replay --file results/receipts.json
python3 gmc.py write-rust
```

`results/` is gitignored. A full receipt log for the default run is about 21 MB because every receipt stores the state before and after the action.

Rust (toolchain required):

```bash
cargo test --manifest-path rust/Cargo.toml
cargo build --release --manifest-path rust/Cargo.toml
```

`gmc.py write-rust` rewrites `rust/Cargo.toml` and `rust/src/lib.rs` from the strings shipped in the Python file, so the kernel in this tree and the kernel the harness emits stay the same text.

## Layout

```text
gmc.py            research harness, gates, receipts, tests
rust/Cargo.toml   gmc-kernel package
rust/src/lib.rs   curvature, energy, checked transfer, C ABI
```

## Why this is not a recovery playbook

Heartbeats, timeouts, and consensus rules name a failure mode and then a procedure. This prototype does not. It only accepts a transfer when the transfer is a descent step on the utilization energy of the current graph, and it records the refusal when the step is unsafe, stale, or unauthorized.

That is a geometric constraint on a simulated graph. It is not yet a distributed system, a mesh network, a multi-agent controller, or an assurance case for an autonomous system. Those are the direction of the work, not properties of this tree.
